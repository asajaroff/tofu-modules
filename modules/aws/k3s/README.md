# k3s

Self-managed [k3s](https://k3s.io/) cluster on AWS EC2, with a scalable control plane (1 or 3 masters, using k3s's embedded etcd) and a scalable worker pool (0-3 dedicated agent nodes). Wraps the [`ec2`](../ec2) module — one call per node role — plus the SSM/IAM/security-group plumbing needed to bootstrap a cluster without ever writing a secret literal into source.

## Features

- **Masters: 1 or 3, never 2.** Embedded etcd needs an odd member count for real quorum tolerance — losing either node in a 2-master cluster loses quorum entirely, with no fault-tolerance benefit over a single node. `masters_count` is validated accordingly.
- **Workers: 0-3.** 0 is valid and matches a single-node deployment (the master schedules pods too).
- **AZ-spread control plane.** Each master/worker lands in a different entry of `subnet_ids`, round-robined — a 3-master cluster is actually resilient to an AZ outage, not just a node failure.
- **No secrets in source or in any instance's boot logs as a human-typed value.** The cluster join token is generated by Terraform (`random_password`), written to SSM Parameter Store as a `SecureString` by Terraform itself — not pushed by any instance. Every node only ever *reads* it (`ssm:GetParameter`); no instance role has write access to anything.
- **No boot-ordering race.** The primary master's endpoint (its private IP) is also written to SSM directly by Terraform, referencing the primary master's own resource attribute — by the time any joiner/worker's `ec2` module call starts, that parameter is already fully created in Terraform's own dependency graph (enforced via `depends_on`), not just hoped-for via a retry loop.

## Usage

```hcl
module "k3s" {
  source = "git::https://github.com/asajaroff/tofu-modules.git///modules/aws/k3s?ref=k3s/v1.0.0"

  name = "k3s-sandbox"

  masters_count = 3
  workers_count = 2

  vpc_id     = dependency.network.outputs.vpc_id
  subnet_ids = dependency.network.outputs.private_subnets

  region                 = local.region
  parameter_path_prefix  = "/non-prod/sandbox/k3s"

  allow_ssh_ips = ["82.169.197.149/32", "89.188.2.30/32"]

  tags = {
    Project = "k3s"
  }
}
```

## Reaching the cluster

No inbound port is opened to the internet for the k3s API — reach it via AWS SSM Session Manager port-forwarding (requires the `session-manager-plugin` locally):

```bash
aws ssm start-session \
  --target <master-primary-instance-id> \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["6443"],"localPortNumber":["6443"]}'
```

Fetch the kubeconfig without an interactive shell:

```bash
aws ssm send-command --instance-ids <master-primary-instance-id> \
  --document-name AWS-RunShellScript --parameters commands='cat /etc/rancher/k3s/k3s.yaml'
```

Patch the resulting kubeconfig's `server:` field to `https://127.0.0.1:6443` to use it against the port-forward from above.

## Architecture

Every node role gets a **static, checked-in** cloud-config (`config/*.yaml`, identical content regardless of `masters_count`/`workers_count`) — the `ec2` module this wraps loads `custom_cloud_config` via a plain `file()` read, which only works against files that already exist in the module source; it can't read something a `local_file`/`templatefile()` resource would generate during the same apply. So nothing per-cluster is baked into the cloud-config at plan time — everything a node needs to discover about *which* cluster it belongs to happens at boot, via its own instance metadata and tags:

1. Fetch its own region from IMDS.
2. Read back its own `k3s-parameter-path-prefix` tag (via `ec2:DescribeTags`) — every node gets this tag from `var.parameter_path_prefix`, so it always knows which SSM path holds its cluster's parameters.
3. Fetch the join token from SSM (`${parameter_path_prefix}/node-token`, `SecureString`).
4. (joiner/worker only) Fetch the primary master's endpoint from SSM (`${parameter_path_prefix}/master-endpoint`).

Then:

- **`master_primary`** (always exactly 1 node): runs `k3s server --cluster-init --token "$NODE_TOKEN"`. This becomes the cluster's first etcd member and the join target for everything else.
- **`master_joiner`** (`masters_count - 1` nodes, 0 or 2): runs `k3s server --server https://$ENDPOINT:6443 --token "$NODE_TOKEN"`. All joiners join through the primary specifically (k3s's documented HA pattern), not through each other.
- **`worker`** (`workers_count` nodes, 0-3): runs the agent installer with `K3S_URL`/`K3S_TOKEN` set.

All three roles share one `aws_security_group` (self-referencing rules for 6443, 2379-2380/etcd, 8472/udp flannel, 10250/kubelet) and one read-only IAM policy (`ssm:GetParameter`/`GetParameters` scoped to `${parameter_path_prefix}/*`, plus `ec2:DescribeTags` for the self-lookup above), attached to every node via the `ec2` module's `additional_security_group_ids`/`additional_iam_policy_arns` hooks.
